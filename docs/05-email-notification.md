# 05 · 邮件通知方案与取舍

> 状态：✅ 已定 —— 阿里云 DirectMail 主发信 + IM 群机器人第二通道；Resend 备选（海外收件场景）。

## 关键前提

公司邮箱是**阿里企业邮箱**（收件方）。这不影响存储，但直接影响发信服务选型：国内邮箱服务商对"海外 ESP + 新域名"的邮件判定激进，新域名通常要约一个月预热期，期间进垃圾箱是常态。发往自己家的通知邮件被吞 = 丢线索。

## DNS 配置（一次性）

前提待确认：**官网域名与阿里邮箱绑定域名是否同域**。同域时按下表，不同域则各管各的、更简单。

| 记录 | 归属 | 说明 |
|---|---|---|
| 根域 MX / SPF / DKIM / DMARC | 阿里企业邮箱（收件） | `_dmarc` 从 `p=none` 起步 |
| `send.` 子域 MX / SPF / DKIM | DirectMail（发信域名） | 发信用子域是标准做法，不污染根域信誉、与收件服务零冲突 |

发信规范：From 必须是自己域（如 `noreply@send.arclink.com`），**访客邮箱放 Reply-To 而非 From**（否则 DMARC 对齐失败必进垃圾箱）。

## 可靠性三件套

1. **阿里邮箱后台把发信域加白名单**——收件人是自己，这是最直接的保险，加了基本免疫预热期问题；
2. **IM 群机器人第二通道**（钉钉/企微 webhook，函数里约 10 行）——表单是高价值低频事件，邮件与 IM 双通道同挂的概率可忽略；
3. **上线前实测一轮**：真实提交 → 检查收件箱/垃圾箱 → 调整。
